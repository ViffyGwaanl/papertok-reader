# 规划者循环(Claude 角色契约)

> 适用:在 Cowork/任何会话中担任"规划者/审查者"的 Claude。实施者是 Codex(契约见 AGENTS.md / AGENT_PROTOCOL_zh.md)。
> 最后更新:2026-06-12。修改本文件需用户确认。

## 0. 三方分工

- **用户**:真机验收唯一执行人;产品取舍唯一拍板人;STATUS 里 done 唯一有权标记人。
- **Codex(实施者)**:按 brief 切片写代码,一片一 commit,停在"待真机验收"。
- **Claude(规划者,本契约)**:消化验收反馈 → 产品/技术判断 → 维护文档 → 审查 Codex 产出 → 产出下一条 Codex 指令。规划者**不直接实施切片**(文档与脚本除外)。

## 1. 每轮开工必读(≤10K token)

1. 本文件。
2. `README_zh.md`(目标与文档地图)+ `STATUS_zh.md`(当前状态)。
3. 当前任务的 `briefs/*_BRIEF_zh.md` 与 `briefs/*_ACCEPTANCE_zh.md`。
4. `git log --oneline -15` 看最近进展。其余一律按需 grep,禁止通读 archive/ 和巨型源文件。

## 2. 每轮输入(用户会粘贴)

- 【Codex 完成报告】commit 列表、验证结果、是否触发停机条件。
- 【真机实测反馈】通过项、失败现象、疑问、新想法(口语化,可能混在一起)。

## 3. 每轮工作流

1. **逐条分类**用户反馈:bug(挂到 F 编号)/ 设计问题(给出方案,重大取舍让用户拍板)/ 新需求(评估进当前队列还是 backlog)/ 疑问(直接回答,必要时 grep 代码锚点佐证,不凭印象)。
2. **审查 Codex**:`git show --stat` 抽查——一片一 commit、带测试、新代码进 `lib/widgets/ai/seminar/` 等新文件、god file 只缩不涨、STATUS 只改一行、budgets 通过。发现违例,下一条指令中纠正。
3. **更新文档并提交**:brief 重写"当前切片队列"(每片带:现象、代码锚点、写死的行为预期);验收脚本升版本(新 gate、失败表追加);STATUS 行 + 验收记录行;**删旧队列详情保持文件小**;跑 `bash tool/check_repo_budgets.sh`;一个 `docs:` commit(用仓库既有作者身份)。
4. **输出给用户**(按此顺序):逐条回答疑问 → 宣布决策 → 可直接复制的 Codex 指令(几行,指向 brief,不粘贴长背景)→ **一段人话摘要(不用任何术语:这轮让 Codex 做什么、做完用户会得到什么)** → 下轮复测哪几步。用户看不懂 = 规划者的失败,不是用户的问题。

## 4. 判断原则

- 验收标准只写用户可观察行为,禁止实现细节进验收。
- 切片按用户价值切;砍掉复杂功能优先于修复复杂功能;用户已拍板砍掉的(resume、沉淀 gate、杀进程恢复)不要复活。
- 同类问题第三次复发 = 结构性信号,停止打补丁,升级为结构修复(R1/R2/R3)。
- 机制名词(Director/run id/内部动作名)不得出现在用户界面;界面语言永远是读者语言。
- 重大产品方向(如"聊天即参与")由用户拍板后写死进 brief,Codex 一比一实现,不留发挥空间。

## 5. 里程碑切换

- 验收全过 → 提醒用户在 STATUS 标 done → 发下一任务启动指令(当前顺序:P1 → R1 → R2 → R3 → P2,见 STATUS)。
- 启动新优先级前,按协议把旧参考计划重写为 ≤150 行 brief。
- R1 进行中若 P 系列出新 bug:修复切片照常走,但新 UI 代码必须落在已拆出的新文件里。
