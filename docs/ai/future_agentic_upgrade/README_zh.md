# PaperTok Reader Future Agentic Upgrade

> 状态：Ready  
> 用途：给 AI agent team 执行的长期升级规格，而不是按人日、月份或季度排期的人类 roadmap。

本目录把 PaperTok Reader 的未来 AI 学习能力整理成可执行的工程文档体系。所有工作按 `Epic -> Capability -> Agent Task -> Gate -> Acceptance` 组织，任何任务在进入实现前都必须明确输入真相、输出产物、允许改动范围、禁止事项、验证命令和 reviewer gate。

## 1. 阅读顺序

1. `00_product_north_star_zh.md`：产品北极星和外部项目融合方式。
2. `01_current_capability_map_zh.md`：现有 PaperTok 能力、可复用模块和缺口。
3. `02_agent_execution_model_zh.md`：AI agent 执行模型、任务模板和禁止写法。
4. `03_epic_index_zh.md`：全部 Epic 的 DAG 依赖图。
5. `implementation_status_zh.md`：本分支代码 artifact、gate 和验证证据。
6. `04_user_facing_activation_plan_zh.md`：用户现在从哪里用、当前还不能用什么、入口任务验收状态和下一步 agent task。
7. `user_decision_summary_zh.md`：用产品决策视角说明哪些功能能用、哪些是内部地基、长期大块要怎么做以及做成后的效果。
8. `05_openmaic_discussion_reference_zh.md`：OpenMAIC 研讨实现方式和 PaperTok 可借鉴边界。
9. `epics/`：每条能力线的执行规格。
10. `gates/`：跨 Epic 复用的质量、安全、资源和 rescue review gate。

## 2. 状态词

| 状态 | 含义 |
| --- | --- |
| `Draft` | 方向清楚，但还不能直接交给 agent 实现。 |
| `Ready` | 依赖、输入、输出、范围、验证和 acceptance 都已锁定。 |
| `Blocked` | 缺少上游任务、数据、工具、设计决策或外部条件。 |
| `In Review` | 实现已完成，正在做 reviewer/rescue gate。 |
| `Accepted` | 通过验收，证据可追溯。 |
| `Deprecated` | 被新 Epic、Capability 或代码事实替代。 |

本目录自身为 `Ready`，表示文档体系和 Epic 规格可以被 agent team 使用。单个 Epic 的任务仍必须按该 Epic 的 task table、task execution defaults 和对应 gate 执行，不允许跳过 reviewer/rescue gate。

## 3. 执行单位

| 单位 | 定义 | 输出 |
| --- | --- | --- |
| `Epic` | 一条完整能力线，例如 AI Seminar、KnowledgeCard、ConceptGraph。 | 可独立追踪的能力文档。 |
| `Capability` | Epic 内可单独交付的用户或平台能力。 | 结构化接口、服务边界、UI 或数据流。 |
| `Agent Task` | 可交给一个 AI agent 执行的最小任务。 | 代码、测试、文档或验证证据。 |
| `Gate` | 进入或完成任务前必须满足的检查。 | 可复用 checklist 和命令。 |
| `Acceptance` | 证明任务完成的具体标准。 | 测试输出、DB 断言、UI 行为、deep link 或截图。 |

## 4. 全局原则

- 不写人日、月份、季度或传统排期，只写依赖、Gate 和 Acceptance。
- 不把 OpenMAIC、MarginNote、WikiLinks、Understand-Anything 当作可复制产品，只抽象可融合能力。
- PaperTok Reader 现有 AI/RAG/Memory 架构是主线，新增能力必须接入现有模块。
- AI 生成内容必须带 provenance。v4 目标下，普通学习动作不默认进入 Review Inbox，而是在当前阅读页或 AI Chat 内完成预览、添加、编辑、合并、忽略或撤销；Review Inbox 只处理同步冲突、批量导入、低置信候选、敏感记忆、来源断裂、重复关系无法判断、跨设备恢复异常等例外场景。
- `ai_index.db`、RAPTOR、GraphRAG 索引默认是可重建派生缓存；用户确认过的卡片、复习记录、笔记和记忆才是用户资产。
- API key 永不同步；外发正文给 LLM 或 embedding provider 必须有功能级开关或明确提示。

## 4.1 v4 目标重置

当前长期目标已从“所有 AI 产物进入 Review 后再应用”调整为“证据驱动、低负担、当前页内联确认”。后续 agent task 必须按下面的优先级推进：

1. 书籍智能索引 2.0：把 ANN 真向量索引、旧索引书籍全局层补建、RAPTOR、GraphRAG 和全书图谱底座合并成同一条能力线；已有 chunk/embedding 优先渐进升级，不默认全量重建。
2. 全书自动图谱与导读地图：默认展示全书主干图，核心节点按关系强度、证据数量和全书中心性选择；选中文本只用于聚焦局部图。
3. AI Chat 原生多角色 Seminar：主入口是 AI Chat 消息流和结构化任务卡，不是独立弹窗、独立页面或 `Choose style` 普通提示词风格；讨论必须支持非固定回合的自然插话、分歧、反驳、重找证据和 Director 调度。
4. 低负担知识保存：KnowledgeCard、Seminar 结论、图谱节点/关系、flashcard 和 Memory 都应优先在当前上下文内联确认；Review Inbox 降级为异常处理中心。
5. Seminar 进程死亡恢复收尾：保留本机 checkpoint、用户确认续跑、provider/model/evidence mismatch gate 和重复续跑保护；该任务优先级放后，只做本机恢复边界收口和 bugfix。

## 5. 当前用户可用性

本目录不是说“所有 Epic 都已产品化”。本节只放用户入口摘要；完整的功能使用路径、入口缺口、agent 任务和验收边界以 `04_user_facing_activation_plan_zh.md` 为准；代码级完成状态和验证命令以 `implementation_status_zh.md` 为准；如果要判断哪些能力值得继续投入，先看 `user_decision_summary_zh.md`。

如果只打开本 README，需要按下面两层理解：

- 用户要找入口：看本节表格的“用户怎么用”列。
- agent 要继续接产品闭环：看 `04_user_facing_activation_plan_zh.md` 的每条用户路径、Gate、验证命令和 `UFA-*` task。

下表的“已接入”只表示当前分支已有代码和测试证据，不等于 `main`、TestFlight 或用户已安装版本可用；未产品化、未发布或仍缺闭环的内容统一列在“当前还不能用”。

注意：表格中仍写有 `Review Inbox` 的路径时，表示当前分支已经存在的旧闭环，不代表 v4 目标要继续把普通学习动作默认送审。后续实现必须逐步把普通保存动作迁回当前阅读页或 AI Chat 卡片内联确认，只把异常场景交给 Review Inbox。

- completed Seminar 历史卡现在有 `保存知识卡`、`编辑后保存`、`加入复习`、`加入我的图谱` 和 `忽略` 入口。`保存知识卡` 会把可追踪 synthesis summary 保存为 `seminar` origin 的 draft KnowledgeCard，保留 SourceRef evidence，不写 ReviewItem、不进入 Review Inbox；`编辑后保存` 会先让用户在当前 AI Chat 对话框中修改知识卡标题和解释，再保存同一类 draft KnowledgeCard；保存成功后同一张卡会显示 `撤销保存`，只移除这张 AI draft 卡，不删除已确认用户资产。`加入复习` 会把同一可追踪 synthesis 作为 due flashcard 加入 Spaced Review，保存后显示 `撤销复习`；撤销只移除未复习过的内联 flashcard，已有复习记录的条目不会被普通撤销删除。`加入我的图谱` 会把同一可追踪 synthesis 保存为 claim 类型 draft ConceptNode，保留 SourceRef evidence，不写 ReviewItem、不进入 Review Inbox、不自动变成正式图谱资产；保存后显示 `撤销图谱`，撤销只移除这张 AI draft 节点并清理它的 incident relations，不删除已确认图谱资产。`忽略` 只收起本张卡片的沉淀建议，不写 KnowledgeCard、ReviewItem、SpacedReview 或 ConceptGraph；用户可点 `恢复操作` 重新显示这些按钮。`异常送审` 仍保留为低置信、冲突或来源异常时的 Review handoff，不再作为普通保存主路径。
- AI Chat Seminar 历史卡的 snapshot 已有卡内子视图：`全部 / 证据 / 角色 / 分歧 / 白板 / 总结 / 异常`。点击 `分歧` 会聚焦分歧正文，隐藏证据片段；点击 `证据` 会回到证据快照。角色发言摘要已经能随 `conversationV2` 保存本轮 evidence refs，并在 `全部` 时间线里显示 `本轮证据`；这些证据 snapshot 现在会保留 SourceRef safe JSON，证据快照、本轮证据和分歧关联证据都可显示 `打开来源 / Open source` 跳回原文。这里仍未完成的是更完整的 contradiction scanner、完整 rebuttal loop、独立详情页 scoped store 和 message part schema migration。
- 恢复续跑提示会区分普通 checkpoint 和读者点名 follow-up：普通 checkpoint 说明点击继续后只为缺失角色再次调用 provider；读者点名续跑说明点击继续后会为读者点名的角色回合再次调用 provider。普通新 run 和恢复后的 queued run 不会继续显示 restored banner。
- 产品决策：Seminar 的长期主入口是 AI Chat 内的 run action 和结构化消息卡，不是另一个割裂页面，也不是 `Choose style` 的普通 prompt 风格。独立 Seminar page 只保留为详情、调试、恢复和兼容入口；角色设置分为 Settings 全局默认和单次 Chat run 临时配置，Settings 全局默认第一片已接入，AI Chat 的 `本次研讨设置` 也已能为下一张任务卡临时设置角色 prompt、启用状态、核验者和最多讨论轮次。
- 图谱页的当前书全书图谱为空时，如果该书已有实际存储的旧版 AI chunk 索引，会显示 `立即生成全局层索引`，用户可在当前书图谱页直接补建单本书全局层；如果只有旧元数据但没有真实 `ai_chunks`，页面会提示先完成 AI Index，不把这本书误判成可补建。
- 图谱页的当前书全书派生图谱区域会显示 `书籍索引状态 / Book index readiness`，纵向视图和宽屏双栏顶部都会把当前书的 `基础索引 / 向量层 / ANN / 全局摘要层 / 图谱层` 分开呈现；基础索引以实际 `ai_chunks` 行数为准，失败原因会显示出来，ANN 未加载 Vec1/sqlite-vec 时会显示暂不可用并保持 fallback。
- `Settings -> AI Index / Library Index` 的书籍列表行现在也会显示 `索引层状态 / Index layers`，把每本书的 `Base / Vector / ANN / Global / Graph` 当前状态直接放在书名下方；同时显示 `现在可用 / Available now` 与 `下一步解锁 / Next unlock`，把技术层状态翻译成用户能理解的能力，例如当前书问答、原文跳转、语义搜索、大书快速召回、本书地图和导读路径。用户不用进入 ConceptGraph 单本书页面，也能先看出哪本书缺基础索引、缺 ANN、缺全局层或缺图谱层，以及补完下一层会带来什么。这个行内状态只读现有索引事实，不外发正文、不自动补建；当某本书 `Base` 已就绪、已有 embedding 且全部 chunk embedding 覆盖完整，但 `Vector` 缺失时，行内会出现 `Upgrade vector layer / 升级向量层`，只把这本书已有 embedding 写入 compact native vector shadow rows，完成后刷新该行状态；当某本书 `Base` 和 `Vector` 已就绪但 `ANN` 缺失时，行内会出现 `Build ANN sidecar / 构建 ANN sidecar`，只用该书已有 compact vector rows 生成 per-book Vec1 sidecar，不写全局 ANN 表、不重新 embedding，构建期间会在同一行显示 group/row 进度；当某本书 `Base` 已就绪但 `Global` 缺失时，行内会出现 `Build global layer / 补建全局层`，只对这本书复用已有 chunk 生成 RAPTOR/GraphRAG 全局层，完成后刷新该行状态；如果这三种单书动作失败，失败原因会留在同一书籍行，按钮切换为 `Retry global layer / Retry vector layer / Retry ANN sidecar`，重试成功后清掉失败提示；如果书籍因部分 chunk embedding 缺失、chunk embedding 维度混用或缺少维度元数据而需要修复基础索引，行内会显示 `Repair base embeddings / 修复基础 embedding`，把这本书送回基础索引队列；队列执行 `rebuild:false` 时会原地补缺失或错维的 chunk embedding，保留已有 chunk，不直接重建 vector/ANN；如果 provider/model、书籍 md5、分块配置或索引算法版本变化导致索引过旧，行内会提示先重建基础索引，并屏蔽旧层补建按钮，避免用旧配置、不完整或不一致向量继续构建 ANN/GraphRAG；基础索引重试仍走同页已有队列，整库 ANN 构建仍走顶部 `ANN 向量索引` 操作入口。
- 同一书籍行现在也会显示基础索引队列的 latest job：queued/running/paused/failed/cancelled 会在行内显示 `Base index job`、进度、阶段、章节/chunk 细节和错误摘要；失败或取消时保留 `Continue indexing / 继续索引` 重试入口，并在基础索引恢复前隐藏 Vector/ANN/Global 派生层补建按钮，避免用户在坏掉或未完成的基础索引上继续补旧层。
